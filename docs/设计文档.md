# 运动眼镜情境化信息交互设计文档

> 文档版本：v0.1.0  · 最后更新：2026-10-20  · 状态：研究阶段

## 1. 项目概述

本项目探索运动过程中如何通过低干扰的信息提示帮助用户，而不是简单把手机地图搬到眼前。业余骑行是当前的初步研究场景，但最终功能由用户调研和原型测试决定。

## 2. 当前问题定义

初始问题是“骑行时低头查看导航不方便”。经过讨论后，问题被重新定义为：运动过程中，什么信息应该在什么时刻出现，以怎样的方式出现，才能帮助用户而不是增加注意力负担。

## 3. 研究假设

1. 业余骑行者不是单一用户群体，需要区分休闲、规律骑行和训练型用户。
2. 常显完整数据、只显示下一条提示、接近关键节点才提示，可能产生不同的安全感和打扰程度。
3. 眼前显示不一定比手机或语音更安全，需要通过行为测试验证。
4. ESP32 适合做手机与反馈设备之间的信息调度节点，不负责完整地图、SLAM 或通用视觉 AI。

## 4. 系统边界

手机网页负责路线、事件设置和测试记录；ESP32 负责 BLE 接收、事件优先级判断和反馈输出；OLED、LED、震动马达是第一版可替换反馈模块。

`手机网页 → BLE → ESP32 信息调度 → OLED / 灯光 / 震动`

## 5. 第一版验证范围

- 手机发送普通、重要、紧急、连接成功、信息确认五种事件。
- ESP32 根据事件选择显示、闪灯或震动。
- 记录连接状态、发送结果和用户对提示的理解。
- 暂不承诺真实导航精度、透明 AR 光学效果或长期骑行安全结论。

## 6. 调研与测试计划

### 用户调研

记录用户目前使用的设备、查看信息的时机、停车或减速行为、最担心的问题和愿意接受的反馈方式。

### 原型测试

比较三种信息策略，并记录理解时间、主动查看次数、主观打扰程度、方向信任感和佩戴意愿。

### 技术测试

验证 BLE 连接距离、事件传输成功率、OLED 显示稳定性、震动和灯光反馈是否容易辨识。

## 7. 待确认内容

- 最终目标用户和主要运动场景
- 眼镜显示是否真的优于语音、灯光或震动
- 选择 OLED、电子纸还是其他显示方案
- ESP32 型号和最终电池方案
- 访谈人数、测试人数和测试结论
- 所有竞品、论文和数据的原始来源
